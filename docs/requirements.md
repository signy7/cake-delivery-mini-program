# 校园定点配送小程序——需求与页面设计

文档状态：需求整理与初始设计  
当前开发阶段：V1（暂不接入支付）

## 1. Business Requirements（业务需求）

**BR-001：** 通过微信小程序替代微信群接龙，实现集中接单与订单整理，减少群消息刷屏及经营者手工处理订单的负担。

业务背景：

- 经营者目前使用微信群接龙，已有两个群，合计超过 300 名成员。
- 群消息较多，接龙体验不佳。
- 经营者希望通过小程序接单，并在固定地点统一配送。

## 2. User Requirements（用户需求）

| ID | 用户 | 需求 |
| --- | --- | --- |
| UR-001 | 学生 | 浏览商品并选择购买数量 |
| UR-002 | 学生 | 填写订单信息并完成下单 |
| UR-003 | 学生 | 在小程序内直接付款 |
| UR-004 | 经营者 | 管理销售的商品 |
| UR-005 | 经营者 | 集中接收和查看订单 |
| UR-006 | 经营者 | 根据订单准备商品并统一配送 |

## 3. Functional Requirements（功能需求）

| ID | 功能需求 | 来源 |
| --- | --- | --- |
| FR-001 | 系统应展示在售商品及价格 | 派生 |
| FR-002 | 学生应能够选择商品和购买数量 | 派生 |
| FR-003 | 学生应能够填写订单备注 | 参考界面及此前确认 |
| FR-004 | 系统应要求学生填写手机号，且不能为空 | 商家明确 |
| FR-005 | 系统应根据订单计算配送费 | 商家提出收费，具体规则待确认 |
| FR-006 | 系统应支持小程序内微信支付 | 商家明确 |
| FR-007 | 系统应保存学生订单，并在支付接入后记录支付结果 | 派生 |
| FR-008 | 经营者应能够新增、编辑、上架和下架商品 | 派生 |
| FR-009 | 经营者应能够集中查看订单信息 | 派生 |
| FR-010 | 系统应支持经营者查看各商品的订购数量以便备货 | 派生 |
| FR-011 | 系统应在每日 14:00 截止当日下单 | 此前确认 |

其中，FR-006 的支付功能属于完整业务需求，但不属于当前 V1 开发范围。

### 配送业务规则

- 统一配送时间：每日 17:00–17:30。
- 商家最初提出两个配送地点：桃李苑东二门、成蹊苑东门。
- 后续讨论中曾将其简化为统一生活区东门，地点是否合并需要确认。
- 商家提出设置 1～2 元配送费。此前还讨论过多份商品免配送费，最终计算规则待确认。
- 学生不选择配送时间或配送批次。

## 4. Non-Functional Requirements（非功能需求）

以下是由业务场景推导的质量要求，具体性能指标尚未确定。

| ID | 质量属性 | 需求 |
| --- | --- | --- |
| NFR-001 | 容量 | 系统设计应考虑现有 300 多名群成员的潜在使用规模 |
| NFR-002 | 可靠性 | 订单成功提交后应可靠保存，避免重复提交产生重复订单 |
| NFR-003 | 安全性 | 学生不得访问经营者管理功能或其他学生的订单信息 |
| NFR-004 | 易用性 | 学生应能够在小程序内完成商品选择和订单提交，不依赖群接龙 |

300 多名群成员是规模依据，不等同于 300 人同时并发。

## 5. 页面设计与 FR 映射

| 页面 | 核心内容及操作 | 对应 FR |
| --- | --- | --- |
| 学生商品浏览页 | 商品图片、名称、价格、选择数量 | FR-001、FR-002 |
| 学生订单确认页 | 商品清单、金额、配送信息、手机号、备注、提交订单 | FR-003～FR-007 |
| 经营者商品管理页 | 商品列表、新增、编辑、上下架 | FR-008 |
| 经营者订单管理页 | 订单列表、订单详情、商品数量及联系方式 | FR-009、FR-010 |

页面参考商家提供的小程序截图，但截图中的搜索、折扣促销等元素不自动构成新增功能需求。

学生和经营者使用同一个微信小程序。管理入口按身份展示，实际权限由云端校验。

## 6. V1 开发范围与验收

### 6.1 当前开发范围

开发顺序：

1. 商品管理：经营者能够创建、编辑并上架商品。
2. 商品浏览：学生能够查看在售商品并选择数量。
3. 订单确认：学生能够填写手机号、备注并提交订单。
4. 订单管理：经营者能够查看提交的订单及备货信息。

### 6.2 V1 验收

- 经营者上架商品后，学生可以浏览。
- 学生能够选择商品数量并填写订单信息。
- 缺少必填手机号时不能提交订单。
- 学生提交订单后，云端能够保存订单。
- 经营者能够查看对应订单。
- 普通学生不能修改商品或查看他人订单。
- 重复提交同一请求不应生成重复订单。
- 不依赖微信支付即可完成上述测试。
- 系统不能将未付款订单显示为支付成功。

### 6.3 暂不开发

- 微信支付及回调
- 退款
- 复杂库存管理
- 配送路线规划
- 配送批次管理
- 优惠券与促销体系

## 7. 待确认事项

| 事项 | 影响 |
| --- | --- |
| 最终配送地点是一处还是两处 | 订单确认页面及订单数据 |
| 单份配送费和多份免配送费规则 | 金额计算 |
| 微信支付接入条件 | 后续支付模块上线 |

这些待确认项不阻塞当前不依赖它们的商品管理、商品浏览和订单基础开发。
