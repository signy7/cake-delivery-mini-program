# 架构与模块边界

状态：初始设计，尚未实现。更新：2026-11-17。
产品功能、V1 范围和验收依据见[需求与页面设计](requirements.md)。

## 已确定的架构

学生与经营者共用一个微信小程序，通过身份区分操作权限。微信云开发的云函数负责业务逻辑，云数据库负责持久化；不引入独立服务器或复杂后端部署。

调用关系：小程序页面 → 云函数（身份、权限、业务校验）→ 云数据库。前端隐藏管理入口只是展示控制；每次管理操作必须由云端校验经营者身份。

## 建议的逻辑模块

以下划分为实现建议，不代表已经实现，也不要求拆成独立服务。

| 模块 | 职责与数据归属 | 边界 |
| --- | --- | --- |
| 身份 | 识别当前用户、读取云端角色 | 客户端不能自授经营者权限 |
| 商品 | 商品维护、上下架、在售商品查询 | 仅经营者可修改；学生只读在售商品 |
| 订单 | 校验商品与数量、计算金额、保存订单快照、经营者查询订单 | 不信任客户端价格或用户标识；订单创建不依赖支付成功 |
| 支付（后续） | 将来处理收款结果 | 订单与支付状态分开；支付接入后不改变订单模块的数据归属 |

商品模块提供当前商品信息，订单模块在提交时重新核验，并保存当时名称、单价与数量，避免商品编辑改变旧订单。公共代码只承载身份校验、格式校验等基础能力。

## 建议代码目录

实施时按实际工程调整；以下目录尚未创建：

- `miniprogram/`：页面与前端调用。
- `cloudfunctions/`：身份、商品、订单业务入口。
- `docs/`：需求、架构和数据依据。

模块调用名称和具体云函数粒度在实现时确定；无需提前引入微服务、网关或 OpenAPI 文档站。
